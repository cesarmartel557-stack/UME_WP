1. Casos de Error
Código HTTPError (JSON)Causa
401 Unauthorized{"code": "rest_forbidden", "message": "Error al obtener autorización.", "data": {"status": 401}}Faltan las cabeceras X-Access-Token o X-Secret-Key, el prefijo no es TK_/SK_, o las credenciales no coinciden con un usuario con capacidad requerida.
400 Bad Request{"code": "no_data", "message": "No se recibieron datos", "data": {"status": 400}}La solicitud se autenticó correctamente pero el cuerpo (body) o los parámetros de la URL están vacíos.
400 Bad Request{"code": "error", "message": "Error al procesar la solicitud.", "data": {"status": 400}}Ocurrió una excepción inesperada (Throwable) durante el procesamiento de los datos.
2. Caso de Éxito (Success)
Código HTTPRespuesta (JSON)Condición
200 OK{"status": "success"} Las credenciales son válidas y se han recibido parámetros en el body (JSON).
3. Ejemplo de Envío de Información
Aunque el código registra el método como POST, el callback process_study_notification está diseñado para intentar leer parámetros de un cuerpo JSON, de parámetros POST o de la Query String.
Headers y JSON Body
URL: https://turnos2.clinicaume.com.ar/wp-json/appointments-api/v1/study-notifications
Headers:
  • X-Access-Token: <tu_token_aqui>
  • X-Secret-Key: <tu_clave_encriptada>
  • Content-Type: application/json
Body:
json

Opción B: Vía Parámetros de URL (Query String)
Si no se envían headers, el código busca los parámetros token y secret en la URL:
https://turnos2.cli.test
  1. Seguridad: El sistema verifica estrictamente que los tokens comiencen con TK_ y las llaves con SK_.
  2. Logs: Cada petición exitosa genera una entrada local dentro del sistema, incluyendo el Host de referencia y el dump de la información recibida para auditoría.
  3. Permisos: El usuario dueño del Secret-Key y Token debe tener explícitamente asignada la capacidad requerida.
  4. Usuario: El usuario y su par de claves seran creados y asignados por un administrador.
Considérese que este es un ejemplo y el cuerpo JSON no requiere el campo metadata.
Se debe enviar información del numero de turno y el resto de información debe mantener un formato y/o estructura estable.
